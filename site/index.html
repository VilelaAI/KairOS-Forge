Humano no circuito

Quatro decisões ficam com o seu time

Os agentes executam. Estas decisões são sempre de uma pessoa, na ordem em que aparecem no fluxo.

  1. Aprovar a SPEC

    Nada é construído sem a especificação aprovada.

  2. Decidir o irreversível

    Mudança difícil de desfazer sai da faixa automática e vai para você.

  3. Fazer o merge

    A fábrica abre o PR; quem mescla é uma pessoa.

  4. Liberar o deploy

    O /lancar pede aprovação explícita antes de publicar.

O painel junta numa caixa de entrada tudo o que espera por alguém: gate humano, SPEC alterada, ciclo escalado e tarefa bloqueada.

O arco

Do pedido ao PR com um comando

Com /kairos-forge:entregar o arco roda sozinho. A falha volta ao agente responsável, dentro de um orçamento declarado; se ele estoura, o ciclo escala para uma pessoa.

  1. Especificar

    SPEC com critérios de aceite, criticada por dois revisores independentes.

    Você aprova a SPEC

  2. Construir

    Time em paralelo, em ondas de até seis agentes.

  3. Validar

    Aceite contra a SPEC, critério por critério, com evidência.

    Falhou: volta para quem construiu

  4. Revisar

    Segurança, QA, performance e DevOps, conforme o escopo.

    Reprovou: corrige e valida de novo

  5. PR

    Aberto com o relatório de cada gate, esperando revisão humana.

    Você faz o merge

Por que confiar

Regras em código, não em prompt

O processo não depende de o modelo lembrar das regras. O que importa é verificado por scripts determinísticos.

Guardrails determinísticos

Hooks bloqueiam comando destrutivo e leitura de segredo antes de acontecer, sem pedir licença ao modelo.

Prova de testes

Todo teste novo roda contra a base sem o patch e precisa falhar. Depois, mutantes nas linhas tocadas precisam ser mortos: teste que não percebe a mudança não prova nada.

Máquina de estados do arco

Transição, orçamento e escalação são decididos por código. O agente não aprova o próprio gate.

Autonomia medida pelo git

A fração de PRs mesclados sem nenhum commit humano sai do histórico, em qualquer CLI. Autonomia é medida antes de ser concedida.

Skills

Um comando para cada etapa

Na ordem natural do fluxo, do primeiro dia num projeto à melhoria semanal. Todas com o prefixo /kairos-forge:.

  • onboardar

    Primeira vez num projeto: gera o CLAUDE.md, as pastas e o contexto de testes.

  • mapear-arquitetura

    Inventário de código legado: componentes, acoplamento e plano de decomposição.

  • diagnosticar

    Mede um sistema existente em seis dimensões e entrega um roadmap priorizado.

  • especificar

    SPEC rastreável antes de qualquer mudança não trivial.

  • analisar-ameacas

    Modelo de ameaças para features sensíveis: autenticação, dados pessoais, billing, IA.

  • desenhar

    Handoff de design para features com interface, com verificação visual.

  • mobilizar

    Time em paralelo executando a SPEC, com posse de arquivo e quadro de tarefas.

  • rodar

    Chama agentes da fábrica em modo conversacional.

  • validar

    Aceite da implementação contra a SPEC, com evidência.

  • revisar

    Revisão do diff antes do PR, com severidade e raio de explosão.

  • lancar

    Deploy com gates, health check em três camadas e rollback com gatilho.

  • mapear-conhecimento

    Grafo de conhecimento do projeto, com proveniência.

  • auditar

    Pontua a fábrica no projeto toda semana e aponta as três maiores lacunas.

  • evoluir

    Escolhe uma capacidade nova da fábrica por semana.

Sob demanda

  • entregar

    O arco inteiro, do pedido ao PR, com correção roteada ao agente responsável.

  • otimizar

    Ciclo de catraca contra uma métrica: muda, mede, mantém ou reverte.

  • migrar

    Modernização de legado por estrangulamento, fatia por fatia.

  • avaliar

    Evals de comportamento não determinístico, com gold set e rubrica.

Instalar

Instale no seu CLI

O mesmo plugin nos quatro CLIs. Os detalhes de cada um estão no README.

/plugin marketplace add VilelaAI/kairos-forge
/plugin install kairos-forge@kairos-forge
/reload-plugins

Para o time em paralelo do /kairos-forge:mobilizar, ative os Agent Teams: export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1

codex plugin marketplace add VilelaAI/kairos-forge
codex   # na TUI: /plugin, escolha kairos-forge e instale

Para o /kairos-forge:mobilizar, instale as personas como roles de subagent:

python3 <plugin>/scripts/sync-multi-cli.py instalar --cli codex --escopo global
git clone https://github.com/VilelaAI/kairos-forge.git
mkdir -p /caminho/do/projeto/.cursor
cp -R kairos-forge/plugin/.cursor/. /caminho/do/projeto/.cursor/

Requer Cursor 2.4 ou mais novo. A instalação por projeto leva também o hooks.json que liga telemetria e guardrails.

git clone https://github.com/VilelaAI/kairos-forge.git
cp -R kairos-forge/plugin/skills/* .opencode/skills/
python3 kairos-forge/scripts/sync-multi-cli.py instalar --cli opencode

A última linha instala as personas como subagents, com a lista de ferramentas de cada uma aplicada como permissão.

Depois de instalar, rode /kairos-forge:onboardar no seu projeto. O início rápido mostra o primeiro pedido do começo ao fim.
